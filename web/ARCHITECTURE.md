# Архитектура веб-версии

## Библиотека и происхождение

40 SVG экспортированы из исходного файла Figma `JYkzetJMeCPbdE5jR5pXhE` штатным векторным экспортом. `assets/manifest.json` связывает ID предмета, размер S/L и роль main/background с файлом, viewBox-размерами и исходным node ID. `provenance.json` фиксирует источник и способ получения, `verification.json` — контрольные суммы. Сжатый пакет `assets.bundle.gz` содержит те же файлы без потерь; `scripts/build.mjs` распаковывает его при чистой сборке. Проверка сборки сопоставляет все 40 файлов побайтово по SHA256.

Рисунок не восстанавливается по картинке и не генерируется. При сборке переиспользуются существующие paths, groups и другие векторные узлы. Штатный SVG viewBox обеспечивает корректные пропорции. S/L выбирает отдельный исходный файл с соответствующей детализацией.

## Модель и компоновка

`src/core.mjs` — текстовый каталог, разрешённые форматы, палитры, разбор названий со склонениями, локальный подбор по темам, простые отрицания, валидатор проекта и история снимков. `planLayout` получает размеры исходных объектов, размещает их в трёх различных схемах и применяет общий коэффициент масштаба. Вариант «Под заголовок» оставляет свободное место; произвольный текст в рисунок не добавляется.

Слой содержит только uid, assetId, role, x/y, scale, rotation и locked. Действия редактора не меняют исходную геометрию. Трансформация задаётся для группы относительно её центра. Фоновые объекты отправляются за главные; пользователь может изменить порядок вручную. Каждый pointer-жест образует один шаг истории. Асинхронный ответ AI отменяется, если пользователь меняет запрос, режим или проект, чтобы не потерять новые правки.

## Рендеринг, цвета и экспорт

`src/svg.mjs` загружает исходники один раз и хранит неизменяемые шаблоны. Исходные HEX/white сопоставляются с восемью цветовыми ролями. Фоновые объекты могут использовать только роли 0–2. При каждой смене палитры цвета восстанавливаются из ролей исходного шаблона, поэтому повторяющиеся цвета пользовательской палитры не разрушают следующее перекрашивание. Геометрия и прозрачности сохраняются. ID внутри SVG и ссылки на них получают уникальный префикс для каждого экземпляра.

Чистый экспорт строится отдельно от интерфейса: в нём нет рамок выделения, маркеров и служебных data-атрибутов. SVG содержит вложенные векторные группы с независимыми трансформациями и встроенными цветами. Растрового canvas и изображений в экспорте нет.

## Интерфейс и данные

`src/app.mjs` связывает DOM, выделение, pointer-управление, свойства, слои, палитры, отмену, JSON-файлы и localStorage. `styles.css` и `styles-refinements.css` задают интерфейс и адаптацию. Данные композиции сохраняются на устройстве пользователя, серверная база не нужна. Валидация импортируемых проектов проверяет список разрешённых форматов, ID библиотеки, уникальность слоёв и числовые ограничения до изменения текущего состояния.

## Необязательный AI-сервер

`api/status.js` сообщает доступность. `api/resolve.js` принимает JSON с темой до 600 символов. `server/semantic.mjs` обращается к DeepSeek по серверному ключу, требует JSON и проверяет ответ по каталогу. Есть тайм-аут 25 секунд, кэш на час, ограничение 12 запросов на клиента за 10 минут и 120 новых запросов в час на экземпляр функции. Эти лимиты не являются распределённым глобальным ограничением; перезапуск или несколько экземпляров меняют их область действия. Провайдерские ошибки не возвращают клиенту секреты и тела ответов.

## Публикация

Статические файлы собираются в `dist/`; серверные модули и .env туда не попадают. Vercel обслуживает статику и две Node-функции. Настроены CSP, запрет встраивания и защитные HTTP-заголовки. Размещение выполнено в существующем тарифе Hobby. Секреты не входят ни в Git, ни в архив передачи.
