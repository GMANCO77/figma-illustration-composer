# План разработки конструктора иллюстраций за один день

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Сделать запускаемый плагин Figma, который собирает редактируемые векторные композиции из предоставленной библиотеки по списку объектов и текстовой теме.

**Architecture:** Обычный локальный плагин Figma: панель управления и код, работающий с документом через Plugin API. Объекты копируются из рабочей библиотеки, а каталог, правила размещения и палитры хранятся в проекте. Для свободных смысловых запросов предусматривается отдельный небольшой сервер AI; ключ хранится только в его окружении.

**Tech Stack:** TypeScript, HTML/CSS, Figma Plugin API, esbuild; Node.js для сборки и необязательного AI-сервера. Интерфейс небольшой, без отдельного фреймворка. Точные версии зависимостей фиксируются при подготовке проекта.

**Spec:** Требования и границы в разделах «Результат» и «Global Constraints» этого документа; исходное задание находится на странице «Задание» рабочей копии Figma.

## Где работаем

- Исходники: `work/illustration-composer/` в текущей рабочей папке Codex.
- Сборка плагина: `work/illustration-composer/dist/manifest.json`, `code.js`, `ui.html`.
- Запуск: настольная Figma, импорт плагина через меню разработки и выбор manifest.json.
- Рабочий файл: https://www.figma.com/design/JYkzetJMeCPbdE5jR5pXhE/
- Библиотека: существующая страница «Библиотека компонентов».
- Новые композиции: отдельная страница «Результаты конструктора» в рабочей копии. Библиотеку не перестраиваем.
- Сдача: `outputs/` — архив проекта, инструкция, примеры SVG, описание архитектуры и материалы демонстрации.

## Результат

Панель с двумя режимами: «По теме» и «По объектам». В ней есть выбор S/L, формата 1:1, 16:9 или 9:16, палитры и композиционного шаблона. Кнопка сборки создаёт три варианта обычными векторными слоями Figma. Доступен экспорт выбранного результата в SVG. Ручное редактирование выполняется инструментами Figma.

Базовый режим темы использует явно описанные теги и словарь метафор. Он работает без сети, но не обещает понимать произвольный текст. Если доступен ключ AI-провайдера, подключается смысловой подбор через сервер; новые объекты AI не рисует. Отсутствие сети не должно ломать сборку по списку объектов.

## Global Constraints

- Использовать только объекты предоставленной библиотеки исходных 20 иллюстраций; количество смысловых объектов и вариантов уточнить инвентаризацией.
- Сохранять геометрию и внутренние элементы объектов; не растрировать.
- Сохранять относительные размеры объектов: применять общий масштаб сцены, без произвольного индивидуального растяжения.
- S и L подставляют соответствующие исходные варианты, а не только меняют размер.
- Поддержать главную и фоновую роли, три исходные палитры и загрузку дополнительной палитры JSON.
- Цвета фона разрешены в объектах; цвета, предназначенные только для объектов, запрещены в фоне.
- Не изменять исходную библиотеку; создавать результаты отдельно.
- Не хранить секреты в плагине, исходниках, архиве и репозитории.
- Не добавлять регистрацию, базу данных, оплату, отдельный веб-редактор и публикацию в магазине в однодневный объём.
- Экспорт: SVG с векторными объектами; проверить повторным импортом.

## Review Focus

1. Нет пары S/L у объекта: понятное сообщение, без молчаливой подмены детализации.
2. Неизвестный запрос или AI вернул чужой ID: не выдумывать объект, предлагать доступные варианты.
3. Общий цвет используется в разных ролях: перекраска по роли и исходному назначению, а не глобальная замена всех совпадений.
4. Разные форматы и крупные объекты: преднамеренное кадрирование допустимо, случайное исчезновение главного объекта — нет.
5. Повторный запуск и экспорт: новые варианты не уничтожают старые; SVG не содержит растровых подмен и конфликтующих идентификаторов.

## Порядок и оценка времени

Оценка — 8–10 рабочих часов после подготовки среды и исходников, с пересмотром после первого часа. Это ориентир, а не гарантия срока.

### 1. Инвентаризация и первый запуск — 1–1,5 часа

**Файлы:** `package.json`, `build.mjs`, `manifest.json`, `src/catalog.ts`, `src/types.ts`, `src/code.ts`, `src/ui.html`.

**Интерфейс:** `indexLibrary(page): CatalogEntry[]`; запись содержит `assetId`, `name`, `tags`, `detail`, `role`, `sourceNodeId`, `baseWidth`, `baseHeight` и цветовые назначения. Каталог привязан к текущему документу и пересобирается после изменения библиотеки.

- [ ] Проверить локальные инструменты сборки и рабочую копию.
- [ ] Составить полный список объектов, S/L, главных/фоновых пар; отдельно отметить скрытые слои и маски.
- [ ] Проверить существующие SVG-drop: использовать как материал для анализа, не считать доказательством готового генератора.
- [ ] Создать оболочку плагина и загрузить в Figma Desktop.
- [ ] Скопировать один исходный объект в отдельный результат и экспортировать в SVG.

**Готово:** собственный плагин запускается, каталог виден, один векторный объект проходит путь «библиотека → результат → SVG».

### 2. Сборка по объектам — 1,5–2 часа

**Файлы:** `src/layout.ts`, `src/scene.ts`, `src/ui.html`, `tests/layout.test.ts`.

**Интерфейсы:** `planLayouts(entries, format): ScenePlan[]`; `renderScene(plan, catalog): Promise<string>`. ScenePlan хранит исходные ID объектов, роли, позиции, порядок слоёв и единый масштаб сцены.

- [ ] Проверить расчёт общего масштаба и сохранение относительных размеров на разных объектах.
- [ ] Реализовать выбор нескольких объектов и три шаблона: компактный, со смещением, со свободной зоной под заголовок.
- [ ] Добавить форматы 1080×1080, 1200×675 и 1080×1920.
- [ ] Добавить S/L; при неполных парах показывать явную ошибку.
- [ ] Проверить три разных набора объектов в трёх форматах и повторную генерацию.

**Готово:** выбор объектов создаёт три композиции, результат редактируется стандартными инструментами Figma.

### 3. Палитры и роли — 1–1,5 часа

**Файлы:** `src/palette.ts`, `src/palettes.json`, `src/ui.html`, `tests/palette.test.ts`.

**Интерфейсы:** `parsePaletteJson(text): Palette`; `applyPalette(node, palette, colorMap, role): void`.

- [ ] Зафиксировать реальные соответствия исходных цветов по ролям, включая контур, свет, тени и фон.
- [ ] Проверить запрет объектных цветов в фоне и некорректный JSON.
- [ ] Реализовать три исходные схемы и загрузку пользовательской схемы одного документированного формата.
- [ ] Переключать главную/фоновую роль через готовые исходные варианты, сохраняя геометрию.
- [ ] Проверить контраст и детали на S и L; отдельно проверить заливки и обводки.

**Готово:** вся композиция согласованно меняет палитру, новая схема загружается без изменения кода.

### 4. Подбор по теме — 1–1,5 часа

**Файлы:** `src/meaning.ts`, `src/asset-tags.json`, `tests/meaning.test.ts`; при наличии AI — `server/index.ts`, `.env.example`.

**Интерфейс:** `resolveTheme(text, catalog, mode): Promise<SelectionPlan>`. SelectionPlan содержит только доступные `assetId`, роли, шаблон и краткое объяснение подбора.

- [ ] Описать теги и несколько осмысленных метафор для фактически существующих объектов.
- [ ] Проверить неизвестный запрос и недопустимые ID.
- [ ] Реализовать локальный подбор с честным сообщением о непонятой теме.
- [ ] Если доступен AI-ключ, подключить серверный подбор и проверять ответ по каталогу; ключ в окружении сервера.
- [ ] Проверить темы про обучение, совместную работу и финансы на доступной библиотеке; при несоответствии изменить примеры.
- [ ] Проверить отключённую сеть: список объектов и локальные темы продолжают работать.

**Готово:** тема приводит к объяснимому подбору объектов. В инструкции ясно указано, используется AI или словарь.

### 5. Экспорт и сквозная проверка — 1–1,5 часа

**Файлы:** `src/export.ts`, `src/code.ts`, `src/ui.html`, `tests/export.test.ts`.

**Интерфейс:** `exportScene(nodeId): Promise<string>` — SVG без промежуточного растра.

- [ ] Добавить скачивание SVG из панели и понятные сообщения об ошибках.
- [ ] Выполнить путь «тема → варианты → ручная правка → новая палитра → SVG».
- [ ] Повторно импортировать экспорт и проверить векторные слои и визуальное совпадение.
- [ ] Проверить дублирование объектов, слои, поворот, маски, скрытые элементы и повторные запуски.
- [ ] Исправить найденные ошибки, выполнить сборку, проверку типов и содержательные тесты.

**Готово:** оба сценария работают, SVG открывается, исходная библиотека сохранена.

### 6. Подготовка сдачи — около 1 часа

**Файлы:** `README.md`, `ARCHITECTURE.md`, `AI-TOOLS.md`, `examples/`, архив в `outputs/`.

- [ ] Подготовить три удачные композиции с описанием запроса, выбранных объектов, формата и палитры.
- [ ] Записать короткую демонстрацию, если доступен инструмент записи; иначе подготовить точный сценарий записи и явно отметить, что видео ещё нужно записать.
- [ ] Проверить инструкцию запуска из чистой папки, включая импорт manifest.json.
- [ ] Описать хранение, поиск, переиспользование объектов, ограничения и использованные AI-инструменты.
- [ ] Упаковать запускаемый проект без секретов и лишних зависимостей.
- [ ] Если пользователь укажет Git-хостинг и даст доступ, разместить исходники и получить ссылку; иначе передать архив и отметить незавершённую публикацию репозитория.

**Готово:** запускаемый проект, инструкция и примеры доступны для передачи. Требование ссылки на репозиторий считается закрытым только после фактической публикации.

## Если времени не хватает

Сначала сокращаем декоративное оформление панели и количество композиционных шаблонов. При недоступном AI сдаём честно обозначенный локальный подбор тем с ограниченным словарём, не называя его универсальным AI. Сохранение вектора, работа по объектам, S/L, перекраска и проверенный экспорт остаются приоритетом. Не подменяем рабочую функциональность заранее подготовленными картинками.

## Точки контроля

- После первого часа: библиотека проиндексирована, первый объект скопирован и экспортирован, понятно состояние среды.
- В середине дня: работает выбор объектов, варианты размещения и форматы.
- За два часа до окончания: прекращаем добавлять функции и проверяем сценарии сдачи.
- Финал: показываем конкретные результаты и честный список оставшихся ограничений.
